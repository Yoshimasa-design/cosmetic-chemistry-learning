# 1. ロードマップの目的

本ロードマップは、設計、データ作成、画面実装、機能追加、公開までの開発順序を明確にするために作成する。

各バージョンでは、実装範囲と完了条件を事前に定義し、設計書を更新してから実装を開始する。

開発は、小規模でも動作する状態を早期に完成させ、その後に段階的に機能と掲載素材を拡張する方針とする。

---

# 2. バージョン管理方針

バージョン番号は、次の形式とする。

```text
Ver.メジャー.マイナー
```

例：

```text
Ver.0.1
Ver.0.2
Ver.0.3
Ver.1.0
```

Gitタグでは、次の形式を使用する。

```text
v0.1.0
v0.2.0
v0.3.0
v1.0.0
```

Ver.0系は試作・開発段階、Ver.1.0を初回公開版とする。

# 16. 各バージョンの開発手順

各バージョンでは、次の順序で作業する。

```text
1. 目的を定義する
2. 設計書を作成または更新する
3. 完了条件を定義する
4. Gitブランチを作成する
5. 実装する
6. 動作確認する
7. 設計書との差異を確認する
8. 変更履歴を更新する
9. コミットする
10. 必要に応じてタグを作成する
```

設計変更が発生した場合は、実装のみを変更せず、対応する設計書も更新する。

---

# 17. 優先順位

開発優先順位は次のとおりとする。

1. 化学的な正確性
2. 教育上の理解しやすさ
3. データの一貫性
4. 基本機能の安定性
5. スマートフォンでの操作性
6. デザイン
7. 高度な機能

見た目を整えることよりも、内容と学習経路が正しく成立することを優先する。

---

# 18. ロードマップの更新

本ロードマップは固定されたものではなく、開発状況に応じて更新する。

ただし、バージョンの目的を途中で大きく変更する場合は、変更理由を `08_変更履歴.md` に記録する。

完了したバージョンの設計内容は原則として上書きせず、変更履歴とGitタグによって追跡できる状態を維持する。
